## 4. Remaining known differences (intentional or blocked)

1. Hero titles use SF Pro instead of Instrument Serif (brand rule: SF Pro).
2. Translucent "glass" over a wallpaper is approximated with solid tokens plus `.ultraThinMaterial` in the sidebar. Real window vibrancy depends on the desktop; the prototype paints a fake wallpaper.
3. Backend gaps prevent: project progress/client, task priority, live presence, leave comments/reminders, team calendar events, monthly accrual, first/second-half selection, SSO. These are shown as unavailable or omitted, never faked.
4. System alerts (quit-while-tracking, update) remain native `NSAlert`s.
5. The prototype's installer/DMG simulation, desktop and Dock mocks are not app UI and are not reproduced.

## 5. Visual verification process

CI job `visual-review` (`.github/workflows/macos-native.yml`):
1. Renders the prototype with headless Chromium (Playwright) for each view in light and dark → `visual-review/reference/<view>-<theme>.png`.
2. Launches the Debug app with `-EffiLensReview <route> -EffiLensReviewAppearance <light|dark>` (DEBUG builds only). The app renders the route at 1200 × 780 and writes its own window to `visual-review/current/<route>-<theme>.png` via `NSView.cacheDisplay` (no Screen Recording permission needed), then quits.
3. Review mode is **not signed in**: screens show their real loading / empty / error states, never fixture data. Onboarding and sign-in are captured in full.
4. Both folders are uploaded as the `visual-review` artifact for side-by-side comparison. Corrected screenshots replace "current" on each run.

Parity is judged by people from these screenshots. The build passing is not evidence of visual parity.
